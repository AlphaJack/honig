# honig

The library that code generated by [`cargo-honig`](https://crates.io/crates/cargo-honig) calls: HTTP adapters, routing,
authentication, codecs and checked types. You do not call it yourself: the generated `api` module re-exports what your
code uses.

## Use

```sh
cargo binstall cargo-honig
cargo honig init path/to/openapi.yaml
cargo add honig@=x.y.z -F client,server
cargo honig generate
```

`init` prints the exact `cargo add` line. Its version is the generator's own: the two are released together. When the
generated code needs a feature that is off, `generate` stops and prints the line that turns it on.

## Features

| Feature | Crate | Adds | Needed when |
|---|---|---|---|
| `client` | tower-service | The generated client: the `Transport` bound over tower services and `TowerTransport` | You generate the client |
| `server` | tower-service | The generated server: a tower `Service`, routing, conditional requests and the wide event | You generate the server |
| `reqwest` | reqwest | `ReqwestTransport`: async client with streaming bodies | Optional: you use this adapter |
| `reqwest-middleware` | reqwest-middleware | `ReqwestMiddlewareTransport`: retries, tracing and caching from your middleware stack | Optional: you use this adapter |
| `ureq` | ureq | `UreqTransport`: blocking client | Optional: you use this adapter |
| `gloo-net` | gloo-net | `GlooTransport`: browser `fetch` on `wasm32` only | Optional: you use this adapter |
| `axum` | axum | `Server::into_axum` and the address of the client from the `ConnectInfo` of axum | Optional: you use this adapter |
| `tracing` | tracing | A span per request and a log line for each wide event | Optional: you use this adapter |
| `tracing-opentelemetry` | opentelemetry | W3C Trace Context: `traceparent` and `tracestate` | Optional: you use this adapter |
| `jiff` | jiff | `date-time`, `date`, `date-time-local` and `time-local` as `jiff` types, and `FullTime` in them | Optional: you want these types |
| `uuid` | uuid | `uuid` as `uuid::Uuid` | Optional: you want these types |
| `url` | url | `uri` as `url::Url` | Optional: you want these types |
| `ipnet` | ipnet | `ipv4-cidr` and `ipv6-cidr` as `ipnet` networks | Optional: you want these types |
| `idn` | idna | `email`, `idn-email`, `hostname` and `idn-hostname` checks | The description calls for it |
| `regress` | regress | `pattern` and `patternProperties` checks (ECMA-262) | The description calls for it |
| `oauth` |  | The `OAuth` 2.0 flows of the client: token grants, device authorization and discovery | The description calls for it |
| `pkce` | sha2 | `Pkce`, `authorization_url` and `exchange_code`: the OAuth 2.0 authorization code flow. Outside wasm32 `Pkce::new` makes a verifier from OS randomness | The description calls for it |
| `cookie` | cookie | `Cookie` parameters and API keys | The description calls for it |
| `multipart` | multer | `multipart/*` bodies and parts | The description calls for it |
| `base64` | base64 | Binary data in JSON (`format: byte`, `contentEncoding`, `base64url`) and `http basic` credentials | The description calls for it |
| `xml` | quick-xml | XML bodies and parts | The description calls for it |
| `simd` | sonic-rs | SIMD for large bodies: JSON with `sonic-rs` (`x86_64` and `aarch64`), the UTF-8 check of text with `simdutf8` and base64 with `base64-simd`. Multipart boundaries use `memchr` with or without it | Optional |
